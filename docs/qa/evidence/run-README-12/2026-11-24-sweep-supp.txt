### README CLI vocabulary lines 455-527
  start is staggered, not an exclusion lock, against validation.
- `lore show <class> [--evidence] [--format json|md]` — prints the compiled
  runbook for one class (human-markdown default); `--evidence` adds the class's
  provenance line plus its evidence trail. Unknown class exits 2 (the registry
  is closed).
- `lore audit [--format table|json|md]` — the PRD US-3 coverage + freshness
  matrix: per registry class, runbook-compiled, check count, real-command count
  (vs the honest `no data` sentinel), and freshness. Freshness is honest:
  `last_validated` is never auto-populated in v0.1 — no code path writes it
  (a lint run is not operator attestation; operator attestation is planned,
  not implemented) — so every runbook says `no data` until a human attests.
  Never a fabricated date. Today's freshness signal is the lint itself:
  `lore validate --execute` flips a drifted runbook to `stale` and carries
  the drift reason. The registry has 13 curated classes PLUS the
  `unclassified` catch-all bucket (14 rows, never 14 classes): the bucket
  row is marked so scripted consumers can tell them apart — JSON carries
  `bucket: true` on the unclassified entry only (curated entries have no
  `bucket` key), and the table/md render it as `[bucket] unclassified` with
  `yes` in the dedicated bucket column (curated rows show `-`).
  Incident coverage (LORE-067, LORE-067-R3) is read from the board under the
  **current working directory** — `.coding-hermes/board/events.jsonl` (plus
  `tasks.jsonl`) — over a 90-day window. A class seen there gets
  `incident_seen: true`; a class named by an in-window event but absent from
  the registry is reported in `summary.uncovered_classes` (a gap you can see
  before its runbook exists), and `summary.incident_count` carries the number
  of in-window events. No board → the incident facts degrade to empty with
  exit 0, and `coverage_note` says the source was unavailable.
- The `lore absorb --window <dur> [--ns N] [--board B] [--source S]` sweep —
  parses a prior evidence trail from stdin (or `--trail-file`), classifies each
  block, groups by class, and prints per-class absorb **proposals** on stdout.
  Every proposal is a real runbook **update** (LORE-069): it diffs the folded
  trail (swept blocks, or the lesson parsed with the sweep's tolerance) against
  the class's existing runbook, so `action` is `"update"` with the
  trail-derived content named in `added.evidence_trail`, and each folded block
  carries `outcome: dead-end|observed` (PRD US-2's dead-end marking). A trail
  that adds nothing is an explicitly empty update. Propose-not-write holds:
  nothing is ever written; an empty trail is an
  explicit empty result (exit 0). `--ns`/`--board` are recorded in the proposal
  provenance (no live lookups — the flags exist for a future integration).
  `--source` (LORE-020) threads the provenance marker into every per-class
  proposal payload, same None-rule as the single-proposal path: omitted, the
  payloads keep their original shape with no `source` key.
