lore turns operational incidents into reusable runbooks: it matches a failure
symptom to a curated class, renders that class's checks, and proposes runbook
updates from accumulated evidence. This is the third tagged release.

**Install (git only — this project is not published to PyPI):**

    uv tool install git+https://github.com/get-h3/lore

**Upgrading from a pre-rename install** (`lore` distribution, v0.1.x):

    uv pip uninstall lore
    uv tool install git+https://github.com/get-h3/lore
    uv tool upgrade get-h3-lore

## Known issues

- **The dependency-drift systemd unit ships disabled.** This release adds
  `deploy/systemd/lore-dep-drift.service` and its timer but installs no
  schedule, so nothing runs until an operator arms it. Enabling it is the
  documented step in `deploy/systemd/README.md`; until then drift is only
  reported when the script is run by hand.
- **A tool install pinned to a previous release keeps reporting that release.**
  `uv tool install`/`uv tool upgrade` on the tag you pinned do not follow new
  tags, so an install made at v0.2.0 reports 0.2.0 after this release until it
  is re-pinned. `uv tool upgrade get-h3-lore` moves it; `uv tool upgrade lore`
  answers "lore is not installed" and is the wrong command.
- **`lore absorb` remains proposal-only.** It returns proposed runbook content
  and writes nothing to a runbook; publishing is deliberately unimplemented.
  This is the intended contract, tracked in `docs/ABSORB-TRIGGER.md`.

## Added

- **Gate-run metrics (LORE-EXPORT-1).** `lore gate` now writes a Prometheus
  textfile: `lore_gate_runs_total` counts runs and `lore_gate_last_success`
  drops to 0 when a verdict is denied, so a gate that has begun refusing is
  visible in a scrape rather than only in an exit status. The read/increment/
  write is file-locked and published by rename, so concurrent invocations do
  not lose counts and an interrupted write leaves the previous metrics intact.
  A missing or unwritable textfile directory fails loudly with exit 1 — the
  export never silently no-ops. Seven tests cover the counter, the gauge,
  corrupt-file recovery, concurrent writers, and both failure modes.

- **Scheduled dependency-drift report (SUP-DEPS-LORE-20261121).**
  `scripts/dep-drift.sh` measures `uv.lock` against PyPI and reports drifted
  pins, with a systemd unit and timer that an operator arms deliberately
  (disabled by default — see Known issues).

## Changed

- Dependency pins refreshed from two tracked supervisor rows. platformdirs
  4.13.5 → 4.14.7, and nine package-scoped pins moved to PyPI latest:
  cachecontrol 0.15.0, certifi 2026.10.23, filelock 4.2.12, markdown-it-py
  4.3.0, msgpack 1.2.4, pip 26.3, py-serializable 2.2.0, pytest 9.2.0,
  ruff 0.17.6. No major-version jump; the suite, linter and formatter were
  re-run under the refreshed pins.
- `README.md` Status and `docs/RELEASE.md` now describe the v0.2.0 cut instead
  of v0.1.0, so the stated last release matches the tag list.
- `README.md`, `docs/INSTALL.md` and `docs/RUNBOOK-STORE.md` describe the
  weekly validate timer as operator-armed rather than implying an installed
  schedule.

## Fixed

- **The release clean-tree gate no longer trips on GitReins judge residue.**
  The judge verdict snapshot directory is ignored, so cutting a release is not
  refused by harness state the release does not ship.
- **The GitReins hook budget is declared above the effective test timeout.**
  The commit guard could previously exceed its own default budget on a full run
  and report the budget failure as the finding instead of the tests.
